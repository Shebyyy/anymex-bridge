    48→### Design Decisions
    49→- **Headless JVM**: No Android Context, no UI code — pure JVM server
    50→- **DEX→JAR conversion**: Uses dexlib2 to parse APK DEX files and convert to loadable JAR
    51→- **Isolated ClassLoaders**: Each extension gets its own URLClassLoader to prevent class conflicts
    52→- **In-memory preferences**: Replaces Android SharedPreferences with ConcurrentHashMap
    53→- **Standardized response envelope**: All endpoints return `{ success, data, error }` matching the Flutter MethodChannel pattern
    54→- **CORS enabled**: Cross-origin support for iOS app web requests
    55→- **Image proxy**: Handles Referer-based anti-hotlinking on manga sources
    56→- **Reflection-based invocation**: Extension methods invoked via reflection since we can't compile against extension interfaces

   143→### Key Design Decisions
   144→- **Same request/response format as MethodChannel**: The remote proxy classes send the exact same JSON payloads that `platform.invokeMethod` sends, ensuring the server can handle them identically
   145→- **Client-side repo browsing**: Repo index fetching/parsing stays on the client (pure HTTP to GitHub). Only source execution needs the server
   146→- **Shared KvStore keys**: Remote extensions use the same repo KvStore keys as their native counterparts, so users don't need to re-add repos
   147→- **`requiresPlugin = false`**: Remote extensions don't need local plugin loading since the server handles it
   148→- **Graceful degradation**: If the server is not configured or not reachable, remote extensions simply won't be registered (no crash)
   149→- **No `dart:async` imports in source methods**: Cleaned up unused imports since cancelRequest is a no-op for remote

   258→## 2. Extension Download Flow
   259→
   260→### 2.1 Download Flow by Extension Type
   261→
   262→**Aniyomi (Android):**
   263→1. APK downloaded from `{repoBase}/apk/{apkName}` to temp directory
   264→2. Optional: save to custom path (`use_internal_anime_extension_loading` / `use_internal_manga_extension_loading` settings)
   265→3. Install via `InstallPlugin.installApk()` (system package manager) OR `platform.invokeMethod('installSourceInternal')` (private/internal install)
   266→4. Installed extensions discovered by `platform.invokeMethod('getInstalledAnimeExtensions')` which scans installed APKs
   267→5. Temp file cleaned up after install (unless custom path)
   268→
   269→**Aniyomi (Desktop):**
   270→1. APK downloaded to `{runtimeDir}/Extensions/Aniyomi/`
   271→2. APK converted to JAR via `BridgeDispatcher().invokeMethod('convertApk')` (sidecar uses `de.femtopedia.dex2jar`)
   272→3. JAR stays on disk at `{extensionsDir}/Aniyomi/{pkgName}.jar`
   273→4. Icon URL and version saved to KvStore as `desktop_ext_icon_{pkgName}` and `desktop_ext_version_{pkgName}`
   274→5. `BridgeDispatcher().invokeMethod('loadExtensions', {folderPath})` scans the folder
   275→
   276→**CloudStream (Android):**
   277→1. `.cs3` file downloaded from `pluginUrl` to `{documentsDir}/AnymeX/cloudstream_plugins/{internalName}.cs3`
   278→2. Written via temp file (`.tmp`) then renamed
   279→3. Loaded via `platform.invokeMethod('loadPlugin', {path})`
   280→4. Metadata saved to KvStore as `cs_meta_{normalizedInternalName}` (JSON with iconUrl, language, version, pluginUrl, repo)
   281→
   282→**CloudStream (Desktop):**
   283→1. Same `.cs3` download to `{documentsDir}/AnymeX/cloudstream_plugins/`
   284→2. Loaded via `BridgeDispatcher().invokeMethod('loadPlugin')` or `BridgeDispatcher().invokeMethod('loadExtensions')`
   285→
   286→**Kotatsu (Android):**
   287→1. JAR downloaded from repo URL to `{documentsDir}/AnymeX/kotatsu_plugins/plugin.jar`
   288→2. Loaded via `platform.invokeMethod('loadExtensions', {folderPath})`
   289→3. Active sources tracked in KvStore as `kotatsu_active_sources` (List<String> of source IDs)
   290→4. Install/uninstall just adds/removes IDs from the active list (no file changes)
   291→
   292→**Kotatsu (Desktop):**
   293→1. Same JAR download to `{documentsDir}/AnymeX/kotatsu_plugins/plugin.jar`
   294→2. Loaded via `BridgeDispatcher().invokeMethod('loadExtensions')`
   295→
   296→**Sora:**
   297→1. Source code (JS/Dart) downloaded from `sourceCodeUrl`/`scriptUrl`
   298→2. Stored **in-memory** as `sourceCode` field on `SSource`
   299→3. Entire installed list persisted as JSON-encoded list in KvStore: `sora-Installed-{type.name}`
   300→
   301→**Mangayomi:**
   302→1. Source code (Dart/JS) downloaded from `sourceCodeUrl`
   303→2. Stored **in-memory** as `sourceCode` field on `MSource`
   304→3. Headers captured via `getExtensionService(target).getHeaders()`
   305→4. Entire installed list persisted as JSON-encoded list in KvStore: `mangayomi-Installed-{type.name}`
   306→
   307→### 2.2 File Formats Summary
   308→
   309→| Type | Format | Storage |
   310→|---|---|---|
   311→| Aniyomi (Android) | `.apk` (Android package) | System package manager OR internal APK dir |
   312→| Aniyomi (Desktop) | `.jar` (converted from APK) | `{runtimeDir}/Extensions/Aniyomi/` |
   313→| CloudStream | `.cs3` (JAR with metadata) | `{documentsDir}/AnymeX/cloudstream_plugins/` |
   314→| Kotatsu | `.jar` (Kotlin JAR) | `{documentsDir}/AnymeX/kotatsu_plugins/` |
   315→| Sora | JS/Dart source code | In-memory + KvStore JSON |
   316→| Mangayomi | Dart/JS source code | In-memory + KvStore JSON |

   319→
   320→There is **no single installed-extensions manifest file**. Each extension type manages its own install tracking:
   321→- **Aniyomi/CloudStream/Kotatsu**: Discovered dynamically from the runtime bridge (Android) or sidecar (desktop) by scanning files/loaded classes
   322→- **Sora/Mangayomi**: Persisted as JSON-encoded lists in KvStore

   404→## 4. Extension Loading (Desktop/Non-Android)
   405→
   406→### 4.1 Architecture Overview
   407→
   408→```
   409→Desktop Flutter App
   410→  └─ BridgeDispatcher
   411→       ├─ JniBridge (JNI direct call via jnigen) [mode: jni]
   412→       └─ SidecarBridge (subprocess JVM via stdin/stdout JSON) [mode: sidecar, DEFAULT]
   413→            │
   414→            ▼ Process.start()
   415→      java -jar anymex_desktop_runtime.jar
   416→```
   417→
   418→### 4.2 BridgeDispatcher
   419→File: `lib/Runtime/Bridge/BridgeDispatcher.dart`
   420→
   421→Two modes:
   422→- **`BridgeType.jni`**: Uses `JniBridge` for direct JNI calls (requires JVM lib loaded in-process)
   423→- **`BridgeType.sidecar`** (default): Spawns a Java subprocess and communicates via stdin/stdout JSON
   424→
   425→The mode is stored in `ExtensionManager.bridgeType` (GetX observable).
   426→
   427→### 4.3 SidecarBridge Protocol
   428→File: `lib/Runtime/Bridge/SidecarBridge.dart`
   429→
   430→**Request format** (JSON on stdin, newline-delimited):
   431→```json
   432→{"method": "loadExtensions", "args": {"folderPath": "/path/to/ext"}, "id": "123"}
   433→```
   434→
   435→**Response format** (JSON on stdout, newline-delimited):
   436→```json
   437→{"id": "123", "status": "ok", "data": [...]}
   438→```
   439→
   440→- Requests are matched by `id` (falls back to auto-increment)
   441→- Stream responses use `status: "ok"` (data chunks), `status: "completed"`, `status: "error"`
   442→- Default timeout: 60 seconds
   443→- Cancellation: `{"method": "cancel", "args": {"id": "123"}}`
   444→
   445→### 4.4 Sidecar Process Startup
   446→```bash
   447→java -Dfile.encoding=UTF-8 -Dsun.stdout.encoding=UTF-8 \
   448→     -Dsun.stderr.encoding=UTF-8 -Xms128m -Xmx512m -noverify \
   449→     -jar /path/to/anymex_desktop_runtime.jar
   450→```
   451→
   452→Startup detected by: stderr line containing `"AnymeX Sidecar Process Started"`
   453→
   454→### 4.5 Desktop Extension Install Flow
   455→
   456→1. APK downloaded from repo
   457→2. `BridgeDispatcher().invokeMethod('convertApk', {apkPath, outJarPath})` → sidecar converts APK to JAR using embedded dex2jar
   458→3. JAR saved to `{runtimeDir}/Extensions/Aniyomi/{pkgName}.jar`
   459→4. `BridgeDispatcher().invokeMethod('loadExtensions', {folderPath})` → sidecar scans directory and loads all JARs
   460→
   461→### 4.6 Desktop vs Android Differences
   462→
   463→| Aspect | Android | Desktop |
   464→|---|---|---|
   465→| Runtime bridge | APK loaded via `DexClassLoader` (`MethodChannel('anymeXBridge')`) | JAR launched as subprocess (`SidecarBridge`) or JNI (`JniBridge`) |
   466→| MethodChannel | `aniyomiExtensionBridge`, `cloudstreamExtensionBridge`, `kotatsuExtensionBridge` | `BridgeDispatcher` (sidecar stdin/stdout or JNI) |
   467→| Aniyomi install | System package manager OR internal APK dir | APK→JAR conversion, stored in Extensions dir |
   468→| CloudStream plugins | `.cs3` loaded from app data dir | Same `.cs3` loading via sidecar |
   469→| Kotatsu plugins | `plugin.jar` loaded via MethodChannel | Same JAR loading via sidecar |
   470→| Cookie/UA handling | `MethodChannel('anymeXBridge')` | `BridgeDispatcher` |
   471→

   587→
   588→No custom auth system. The app delegates to external services:

   595→### 6.4 Per-Source Preferences
   596→
   597→Per-source preferences are NOT stored in the local database. They are:
   598→1. Retrieved from the extension at runtime via `getPreference()`
   599→2. Saved back via `setPreference()` which calls the native bridge (Android: SharedPreferences via MethodChannel, Desktop: sidecar/JNI, Remote: HTTP to server)
   600→3. On the server side (Task 1 JVM Bridge Server), preferences are stored in-memory `ConcurrentHashMap`
